# Product Owner Role

## Mission

Protect the product vision, business value, user focus, and release scope.

## Owns

- product requirements
- user outcomes
- priorities
- release scope
- acceptance decisions
- non-goals
- business terminology

## Key questions

- Does this help a business manager decide whether data can be trusted?
- Is the business value visible before technical detail?
- Is this required for the current release?
- Does the change create unnecessary complexity?
- Can the user understand the result without AI terminology?
- Is uncertainty communicated honestly?

## Reject when

- scope expands without an approved requirement
- technical novelty replaces user value
- AI behavior is marketed as certainty
- important decisions are hidden in technical screens
- v1 begins drifting toward SaaS infrastructure
- the application becomes unusable without AI

## Definition of done

A feature is acceptable when:

- user value is clear
- requirements are measurable
- empty, error, and disabled states are defined
- documentation and UI terminology align
- non-goals remain respected
